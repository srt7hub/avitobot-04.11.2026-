# Онбординг клиента — путь и чек-лист (для ops)

Операционная процедура запуска нового клиента: от заявки до работающего бота
на его объектах. Опирается на реальные шаги системы (создание тенанта, ключи
Авито, сборка промпта, перевод в ACTIVE, включение polling).

Связанные документы:
- `tasks/client-onboarding-brief.md` — вопросы анкеты + промпт сборки customPrompt
- `tasks/create-onboarding-form.gs` — генератор двух Google-форм

---

## Путь клиента (этапы)

```
1. Заявка
2. Сбор данных (2 формы)
3. Создание клиента в системе
4. Сборка customPrompt (ИИ) + заведение объектов
5. Подключение Авито
6. Тест в песочнице
7. Запуск (ACTIVE + polling)
8. Контроль первых дней
```

---

## Этап 1. Заявка

Клиент оставил заявку (написал/позвонил). На выходе этапа у вас есть:
имя, контакт, понимание сколько у него объектов.

- [ ] Зафиксирован контакт клиента (телефон / Telegram)
- [ ] Известно число объектов (1 или несколько — влияет на число «Карточек объекта»)

---

## Этап 2. Сбор данных (две формы)

Отправляем клиенту две Google-формы (созданы скриптом `create-onboarding-form.gs`).

- [ ] Отправлена **Форма 1 «Правила бизнеса»** — заполняется один раз
- [ ] Отправлена **Форма 2 «Карточка объекта»** — заполняется на КАЖДУЮ квартиру
- [ ] Получены ответы по Форме 1
- [ ] Получены ответы по Форме 2 на все объекты клиента

> Если клиент тянет с заполнением — здесь обычно главная задержка онбординга.
> Лучше пройтись по форме вместе с ним голосом.

---

## Этап 3. Создание клиента в системе (ops)

Ops-кабинет → создать клиента (`POST /api/ops/clients`).

- [ ] Создан тенант: имя, slug, botName (имя бота из Формы 1)
- [ ] Заданы доступы менеджера клиента (email + пароль) — клиент войдёт в свой кабинет
- [ ] Telegram для уведomлений (если есть): `telegramBotToken` / `telegramChatId`

> При создании тенант получает `status: TRIAL` и автоматически — шаблон-рыбу
> в `customPrompt` (см. promptTemplate.ts). На следующем этапе мы заменим её
> на собранный под клиента промпт.

---

## Этап 4. Сборка customPrompt + объекты

### 4а. customPrompt из ответов Формы 1
- [ ] Взять ответы Формы 1 + промпт сборки (раздел C в `client-onboarding-brief.md`)
- [ ] Прогнать через ИИ (ChatGPT) → получить готовый customPrompt
- [ ] Проверить глазами: нет дублей правил Авито, нет кода двери/wifi в тексте, ≤ ~1500 символов
- [ ] Вставить в ops → вкладка «Промпт» → поле «Доп. инструкция клиента» → Сохранить
- [ ] Свериться с превью «Итоговый промпт» — база + секция собрались без задвоения

### 4б. Объекты из ответов Формы 2 (на каждую квартиру)
- [ ] Создан объект: название, адрес, описание
- [ ] Заполнены защищённые поля: код двери, wifi (сеть+пароль), инструкция заезда
- [ ] Особые условия квартиры (если были в Форме 2) — учтены
- [ ] FAQ под объект (если клиент дал частые вопросы) — добавлены

---

## Этап 5. Подключение Авито

Клиенту нужно дать боту доступ к своей переписке Авито. Два пути:
**OAuth** (клиент авторизуется кнопкой в своём кабинете) или **ключи**
(Client ID / Secret / User ID заводятся в ops).

- [ ] Получены/заведены креды Авито (`avitoClientId`, `avitoClientSecret`, `avitoUserId`)
- [ ] Сохранены: ops → Avito (`PUT /clients/:id/avito`) ИЛИ клиент прошёл OAuth в кабинете
- [ ] **Тест подключения**: ops → «Тест Авито» (`POST /clients/:id/avito/test`) → должен вернуть число чатов
- [ ] (если несколько объявлений) Объекты привязаны к нужным avitoItemId

> Без успешного теста дальше идти нельзя — бот не сможет читать/отвечать.

---

## Этап 6. Тест в песочнице

До запуска на реальных гостях — проверяем бота во вкладке «Тест бота».

- [ ] Выбран нужный объект в селекторе песочницы
- [ ] Заданы типовые вопросы гостя: бронь, цена, отмена, «во сколько заезд»
- [ ] Бот отвечает по customPrompt клиента (тон, условия отмены/торга — его)
- [ ] Бот отвечает по FAQ объекта
- [ ] **Проверка гейтинга**: в сценарии «не оплатил» бот НЕ выдаёт код двери; в «заехал» — выдаёт
- [ ] Клиенту показан результат, правки в customPrompt/FAQ внесены при необходимости

---

## Этап 7. Запуск

Бот пуллит только клиентов со `status: ACTIVE` И `pollingEnabled: true`.
Оба флага надо включить — иначе бот молчит.

- [ ] Тенант переведён в `ACTIVE` (ops → `PUT /clients/:id` со `status: 'ACTIVE'`)
- [ ] Включён polling (ops → «Перезапустить бота» / `POST /clients/:id/bot/restart` —
      ставит `pollingEnabled: true` и сбрасывает счётчик ошибок)
- [ ] Проверено, что в дашборде клиента бот в статусе «работает»
- [ ] (контрольно) В реальном чате Авито гость пишет — бот отвечает

---

## Этап 8. Контроль первых дней

- [ ] Первые 1–2 дня просмотрены диалоги (ops → Диалоги) на адекватность ответов
- [ ] Проверено, что нет ложных эскалаций / странных ответов
- [ ] Собрана обратная связь клиента, при необходимости докручен customPrompt/FAQ
- [ ] Клиенту объяснено: где смотреть диалоги, как править FAQ, как тестировать в песочнице

---

## Быстрый чек-лист (свёрнуто)

```
[ ] 1. Заявка: контакт + число объектов
[ ] 2. Отправлены и заполнены обе формы
[ ] 3. Создан тенант (email/пароль клиента, botName)
[ ] 4a. Собран customPrompt из Формы 1 → вставлен в ops, превью ок
[ ] 4b. Заведены объекты из Формы 2 (адрес, код двери, wifi, FAQ)
[ ] 5. Авито подключён + «Тест Авито» прошёл
[ ] 6. Песочница: ответы корректны, гейтинг кода двери работает
[ ] 7. status = ACTIVE + polling включён → бот «работает»
[ ] 8. Первые дни под контролем, обратная связь учтена
```

---

## Частые грабли

- **Бот молчит после запуска** → проверь оба флага: `status: ACTIVE` И `pollingEnabled: true`.
  Только TRIAL или только polling — недостаточно.
- **Код двери выдаётся не вовремя** → данные попали в текст customPrompt вместо
  полей объекта. Чувствительное — только в поля Property (там гейтинг по фазе).
- **Промпт задвоился** → в customPrompt вставили полный системный промпт вместо
  только бизнес-секции. customPrompt = доп. инструкция, не замена базового.
- **«Тест Авито» падает** → неверные креды или не пройден OAuth. Без зелёного
  теста бот работать не будет.
```
